# 抽奖姬

**开发者：想吃金丝虾球** · Windows 10/11 x64 · 当前版本 2.3.5

[简体中文](README.md) | [English](README.en.md)

> V2.2.0 新增视频评论抽奖、指定楼中楼范围、发布时间筛选和全局空关键词参与。详见 [更新日志](CHANGELOG.md)。

V2.2.1 统一项目标识为 `bili-danmaku-lottery`，作为后续更新基线。旧版用户需要安装新版，旧版设置和安装登记不自动迁移。


面向 B 站直播互动的桌面工具：用关键词弹幕参与抽奖，或按报名先后排队，并通过竖向小窗展示名单和中奖结果。

首次启动房间号为空；输入后自动保存在本机，下次打开恢复。可直接粘贴完整 B 站直播链接，手动删空房间号后下次保持为空。不会自动开始收集。

| 功能 | 说明 |
| --- | --- |

| 礼物排序 | 可选按启用期间已入队者的付费礼物累计金额排序，同金额按最初入队顺序；显示累计金额 |

| 抽奖权重 | 舰长、提督、总督、普通本房间粉丝、其他观众五档，默认均为 1；支持逐人修改和全部恢复为 1 |

| 直播竖窗 | 支持置顶、最小化、缩放、自适应字号；抽取人数同步主界面，抽奖后显示中奖者 |
| 照片背景 | 选择本地照片、恢复默认、调整背景压暗程度 |

## 下载与开始使用

1. 打开[Releases](https://github.com/csudmj/bili-danmaku-lottery/releases)，推荐下载 `bili-danmaku-lottery-2.3.5-x64.exe` 并安装；安装版支持程序内更新。GitHub 自动提供的 Source code 是源码，不是可运行软件。
2. 如选用 `bili-danmaku-lottery-Windows-x64-v2.3.5.zip` 免安装版，请完整解压到可写目录，双击 `抽奖姬.exe`。保留同目录的 `resources`、`locales`、DLL 等文件；无需安装 Node.js 或 Python。
3. 点击“登录 B 站”，在软件打开的官方网页自行登录。软件会话与其他浏览器独立，确认登录成功后网页自动关闭。
4. 选择抽奖或排队，设置房间号、互动词和粉丝牌条件。
5. 点击“开始收集”。状态变为“正在获取弹幕”后，再让观众发送关键词；连接成功自动打开小窗。
6. 抽奖时点击“抽取”；排队时按顺序服务观众，再手动移除对应人员。

版本变化统一见[更新日志](CHANGELOG.md)；上传源码与发布步骤见[发布与升级指南](docs/发布与升级指南.md)。

## 规则与常见操作

- **匹配：** 使用包含匹配。例如关键词“喵喵喵”可以匹配“我要喵喵喵”，不能匹配“喵喵”。只收集开始之后的弹幕，不补录历史消息；无有效 UID 的消息不能参与。
- **去重：** 同一 UID 每轮只参与一次。已中奖者本轮不再中奖；已移除者本轮不能重新加入。重置后可重新报名。
- **排队：** 上限默认 20，可设 1-10000，限制的是当前等待人数。开始后调整需要点击“应用”，不能低于当前队列人数。满员时不建立候补队列；出现空位后，未入队者需重新发送关键词。
- **专属与身份权重：** 新入选时专属 UID 优先，其次匹配无 UID 的完整昵称规则，再按大航海身份、本房间粉丝牌、其他观众分类；全部默认 1。未知大航海身份按粉丝牌归类。编辑专属名单只影响之后新入选者，需追溯时选择“应用到全部待抽”。全部恢复为 1 不清空专属名单。
- **权重：** 每次中奖概率等于本人权重除以当前剩余参与者总权重。多人抽取逐个执行，中奖者移出后重新计算；权重高不等于必定中奖。
- **暂停 / 继续收集：** 保留名单、中奖和权重，继续时沿用本轮条件。
- **开始收集：** 归档上一轮并开启新一轮，未抽奖或无人参与也记录。
- **小窗控制：** 抽取人数同步主界面；收集控制统一放在主界面。
- **关闭或最小化小窗：** 不清空名单，不主动停止收集；主界面可以重新打开。
- **退出主程序：** 不恢复正在进行的活动；各模块最近 20 轮参与名单与结果可在“历史记录”查看，专属权重名单保留。

抽取会自动暂停收集。收集时参与条件锁定；暂停后可修改下一轮条件，点击“开始收集”生效。“继续收集”仍沿用当前轮次条件。实时弹幕只显示最近 2000 条，不会因此删除已入选者。

## 视频抽奖

选择“B站视频”，切换“弹幕抽奖”或“评论抽奖”，输入 BV 号 / 完整视频链接。弹幕需登录投稿账号，评论可选其他人的公开视频。评论范围默认仅主评论；“仅指定主评论下的回复”需要该主评论的数字 ID，或含 root_id / #reply 的完整评论链接，不包含主评论自身。

起止时间使用本机时区，精确到秒且包含边界。起始留空不限；结束留空时，抽奖前重新分页读取，以点击抽奖时刻截止。读取期间可取消 / 重置；读取失败不抽奖。填固定结束时间时使用已生成的名单。关键词留空表示发言即可，其他条件仍有效。历史记录保留实际截止时刻。

## 从源码开发

技术栈：Electron 35、React 18、TypeScript、Vite 6。

使用 Windows、Node.js 22.13 或更高的 22.x 版本，以及 pnpm 10。在项目根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm exec electron --version
pnpm run dev
```

若 pnpm 提示依赖构建脚本未获批准，请执行 `pnpm approve-builds`，批准 `electron` 和 `esbuild` 所需安装脚本，再执行 `pnpm rebuild`。首次安装需要联网下载依赖和 Electron。

```sh
pnpm test
pnpm exec tsc --noEmit
pnpm run build:win
```

Windows 安装包、ZIP、blockmap 和 latest.yml 输出到 `release/v版本号/`。打包脚本只收集运行时资源，不打包测试、缓存或个人登录数据。自动化测试使用网络替身，覆盖筛选、去重、排队容量、移除、权重抽取和窗口状态同步；不等同于实时 B 站连接测试。

仓库提供手动触发的 Windows 构建工作流，产物上传到 Actions artifacts；不会自动发布 Release。首次上传后尚需在 GitHub 环境实际运行验证。

## 视频抽奖与历史记录

选择左栏“B站视频”，在应用内登录投稿账号，输入自己的 BV 号或视频链接，点击“读取视频”；选择分P和关键词后获取名单。平台未提供或已删除的弹幕不在读取范围。单分P达到 1000 条、缺少可靠身份或分页异常时停止导入，不用部分名单抽奖。名单生成后可调整权重、移除人员、抽奖和复制结果。直播与视频参与名单独立，专属权重名单共用。

左栏“历史记录”按“B站直播”和“B站视频”分块查看，每个模块独立保留最近 20 轮有参与者的活动。打开时默认选择当前所在模块，直播抽奖和排队带有类型标记。同轮多次抽奖合并在一条活动内；重置开始新轮次，排队记录包含参与者、移除状态、最终等待顺序及启用时的礼物金额。历史只供回看，不会重新加入当前名单。

直播轮次：再次点击“开始收集”会将上一轮归档并开启新一轮，未抽奖也会记录。“暂停收集 / 继续收集”保留名单、中奖结果和权重；继续沿用本轮条件。
