# 抽奖姬

**开发者：想吃金丝虾球** · Windows 10/11 x64 · 当前版本 1.4.1

[简体中文](README.md) | [English](README.en.md)

面向 B 站直播互动的桌面工具：用关键词弹幕参与抽奖，或按报名先后排队，并通过竖向小窗展示名单和中奖结果。

## 功能

| 功能 | 说明 |
| --- | --- |
| 关键词抽奖 | 弹幕包含指定互动词即可匹配，按 UID 去重，可一次抽取多位 |
| 粉丝牌筛选 | 不限粉丝牌，或要求佩戴本直播间粉丝牌；不单独检查点亮状态 |
| 顺序排队 | 按程序收到符合条件弹幕的顺序入队，可设置当前等待人数上限 |
| 手动移除 | 主界面与小窗均可移除待抽观众或排队者 |
| 抽奖权重 | 默认每人 1，可在主界面为待抽者设置 1-10000 的整数权重 |
| 直播竖窗 | 支持置顶、最小化、缩放、抽奖和重置；最新中奖者显示在按钮下方 |
| 照片背景 | 选择本地照片、恢复默认、调整背景压暗程度 |
| 状态提示 | 明确显示登录与收集状态；小窗不显示登录账号昵称 |

## 下载与开始使用

1. 打开本仓库的 **Releases**，下载 `抽奖姬-Windows-x64-v1.4.1.zip`。GitHub 自动提供的 Source code 是源码，不是可运行软件。
2. 完整解压到可写目录，双击 `抽奖姬.exe`。保留同目录的 `resources`、`locales`、DLL 等文件；无需安装 Node.js 或 Python。
3. 点击“登录 B 站”，在软件打开的官方网页自行登录。软件会话与其他浏览器独立。
4. 选择抽奖或排队，设置房间号、互动词和粉丝牌条件。
5. 点击“开始收集弹幕”。状态变为“正在获取弹幕”后，再让观众发送关键词；连接成功自动打开小窗。
6. 抽奖时点击“抽取”；排队时按顺序服务观众，再手动移除对应人员。

完整图文教程：[PDF 使用说明](docs/抽奖姬_v1.4.0_图文使用说明.pdf)。教程基于 1.4.0，操作同样适用于 1.4.1；1.4.1 更换了应用标识，升级后需重新登录，并按需重新选择背景。

## 规则与常见操作

- **匹配：** 使用包含匹配。例如关键词“喵喵喵”可以匹配“我要喵喵喵”，不能匹配“喵喵”。只收集开始之后的弹幕，不补录历史消息；无有效 UID 的消息不能参与。
- **去重：** 同一 UID 每轮只参与一次。已中奖者本轮不再中奖；已移除者本轮不能重新加入。重置后可重新报名。
- **排队：** 上限默认 20，可设 1-10000，限制的是当前等待人数。开始后调整需要点击“应用”，不能低于当前队列人数。满员时不建立候补队列；出现空位后，未入队者需重新发送关键词。
- **权重：** 每次中奖概率等于本人权重除以当前剩余参与者总权重。多人抽取逐个执行，中奖者移出后重新计算；权重高不等于必定中奖。
- **停止收集：** 保留名单、中奖和权重，可再次开始。
- **主界面重置：** 清空本轮并暂停，可修改模式或条件后开始。
- **小窗重置：** 清空本轮，沿用原条件重新连接收集。
- **关闭或最小化小窗：** 不清空名单，不主动停止收集；主界面可以重新打开。
- **退出主程序：** 不恢复本轮名单和权重。需要保留结果时，先使用“复制中奖名单”。

抽取会自动暂停收集。当前轮次已有参与记录或正在收集时，模式、房间、关键词和粉丝牌条件锁定，修改前需重置。实时弹幕只显示最近 2000 条，不会因此删除已入选者。

## 从源码开发

技术栈：Electron 35、React 18、TypeScript、Vite 6。

使用 Windows、Node.js 22.13 或更高的 22.x 版本，以及 pnpm 10。在项目根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm exec electron --version
pnpm run dev
```

若 pnpm 提示依赖构建脚本未获批准，请执行 `pnpm approve-builds`，批准 `electron` 和 `esbuild` 所需安装脚本，再执行 `pnpm rebuild`。首次安装需要联网下载依赖和 Electron。

```sh
pnpm test
pnpm exec tsc --noEmit
pnpm run build:win
```

Windows ZIP 输出到 `release/v版本号/`。打包脚本只收集运行时资源，不打包测试、缓存或个人登录数据。自动化测试使用网络替身，覆盖筛选、去重、排队容量、移除、权重抽取和窗口状态同步；不等同于实时 B 站连接测试。

仓库提供手动触发的 Windows 构建工作流，产物上传到 Actions artifacts；不会自动发布 Release。首次上传后尚需在 GitHub 环境实际运行验证。
